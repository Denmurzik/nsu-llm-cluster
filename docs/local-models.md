# Свои файлы моделей («Мои модели»)

Развёртывание берёт модель не только с Hugging Face, но и из файла GGUF на главном сервере. Такие модели живут в каталоге
`models/local/<имя>/` тома зеркала `llm-main-hf`; для развёртываний и нод это репозиторий `local/<имя>`. Ноды скачивают их
через то же зеркало (`https://<PUBLIC_HOSTNAME>/hf/...`, docs/hf-mirror.md), с `Range` и докачкой, как модели с Hugging Face.
Поддерживаются и многофайловые модели `-0000N-of-0000M.gguf`.

## Как положить файл

**Через портал.** Администрирование → «Мои модели» → «Загрузка файла». Файл любого размера идёт частями (по умолчанию
32 МиБ, `UPLOAD_CHUNK_MIB`):
- загрузку можно поставить на паузу и продолжить;
- после обрыва связи или закрытия страницы она продолжается с того же байта: в списке «Загрузки» нажмите «Продолжить» и
  выберите тот же файл;
- многофайловую модель выбирайте целиком, все части сразу: они попадут в одну модель;
- ожидаемую sha256 можно указать (для одного файла). Портал в любом случае считает сумму после загрузки и показывает её
  в каталоге, а указанную сверяет;
- после загрузки контроллеры портала проверяют sha256 и заголовок GGUF. Только потом файл появляется в каталоге. Для
  файла в сотни ГБ проверка идёт несколько минут, прогресс виден в списке загрузок.

Незавершённая загрузка, которая 7 дней не получала данных, отменяется сама.

**Папкой на главном.** Положите файлы в каталог `models/` тома (scp, rsync, SMB, USB). В контейнере главного это
`/var/lib/llm-hf/models`, на хосте — каталог тома Docker:

```bash
docker volume inspect llm-main-hf -f '{{ .Mountpoint }}'      # обычно /var/lib/docker/volumes/llm-main-hf/_data
sudo rsync -P DeepSeek-R1-UD-IQ1_S-0000*-of-00003.gguf /var/lib/docker/volumes/llm-main-hf/_data/models/
# или через контейнер
docker cp ./my-model-Q4_K_M.gguf llm-main:/var/lib/llm-hf/models/
```

- Кладите файлы прямо в `models/`. Портал сам перенесёт их в `models/local/<имя>/`, когда копирование закончится. Имя —
  имя файла без `.gguf` и без суффикса части `-0000N-of-0000M`, поэтому все части одной модели оказываются вместе.
  Файл, скопированный сразу в `models/local/<имя>/`, тоже будет найден, но не заменяйте так файл модели, которая уже
  работает: пока портал не проверит новую версию, файл не отдаётся нодам и не предлагается развёртываниям.
- Портал ищет новые файлы раз в минуту (`LOCAL_MODELS_SCAN_S`) и по кнопке «Найти файлы в каталоге». Файл берётся, когда
  не меняется 30 секунд (`LOCAL_MODELS_SETTLE_S`), так что копирование, которое ещё идёт, не мешает.
- У каждого файла проверяется заголовок GGUF. Файл, который не читается, остаётся в каталоге «Мои модели» с причиной.
  Модель без части получает пометку «Не хватает частей».
- Имена файлов и каталогов, начинающиеся с точки, пропускаются: например, временные файлы rsync. Символические ссылки
  тоже пропускаются: модель не может ссылаться на файл вне тома.
- В именах файлов и каталогов допустимы только латинские буквы, цифры, точка, дефис и подчёркивание. Файл с пробелом
  или другим символом остаётся в каталоге «Мои модели» с ошибкой и просьбой переименовать его.
- Нодам и развёртываниям доступны только проверенные файлы. После каждой проверки портал пишет их список с размером,
  временем изменения и sha256 в `models/local/<имя>/.manifest.json`. Зеркало отдаёт только файлы из этого списка, и
  только пока они не менялись.

## Каталог «Мои модели»

Для каждой модели в каталоге видны:
- файлы с квантом, размером, архитектурой и контекстом модели из заголовка GGUF;
- оценка памяти при контексте по умолчанию (`DEFAULT_CTX_PER_REQUEST × DEFAULT_PARALLEL`);
- происхождение файла: загружен в портале или найден в каталоге, для загруженных ещё и sha256;
- развёртывания, которые используют модель.

Модель или отдельный файл со всеми частями удаляется кнопкой в таблице. Пока модель нужна какому-нибудь развёртыванию,
удалить её нельзя: портал называет эти развёртывания.

## Развёртывание

В мастере развёртывания на вкладке «Свои файлы» выберите файл. Дальше всё как с Hugging Face:
- оценка памяти и размещение split по слоям читаются из локального файла;
- поды получают `--hf-repo local/<имя> --hf-file <файл>`, многофайловые модели скачиваются по частям;
- новая версия файла с тем же именем не берётся нодой из её кэша. ETag файла в зеркале — его sha256 (у файлов из
  каталога — размер и время изменения), коммит модели меняется вместе с файлами. Части многофайловой модели нода
  скачивает заново, когда меняется их ETag (`<часть>.etag` рядом с файлом в кэше ноды). Работающие поды новую версию
  не подхватывают: перезапустите развёртывание;
- свои модели идут через зеркало главного всегда, даже при `HF_MIRROR_ENABLED=false`: больше их нигде нет.

Свои файлы запускаются только на llama.cpp.

## Лимиты и место

- `LOCAL_MODELS_MAX_GIB`: предел общего размера своих моделей (0 — без предела). Загрузка, которая его превысит, не
  начинается, портал показывает, сколько занято.
- Свободное место тома проверяется перед загрузкой: файл, незавершённые загрузки и запас 2 ГиБ. Если места не хватает,
  портал отвечает, сколько свободно и сколько нужно.
- Загрузки портала и кэш зеркала Hugging Face делят один диск. Каждая сторона проверяет свободное место перед записью,
  но место, занятое другой, она не резервирует. Скачивание большой модели с Hugging Face во время загрузки своей модели
  может исчерпать место: тогда запись, которая идёт второй, получает понятную ошибку (`507`), и загрузку можно
  продолжить, когда место освободится. В занятое своими моделями (`LOCAL_MODELS_MAX_GIB`) входят и файлы, лежащие в `models/` и ещё не
  перенесённые.
- Свои модели не входят в лимит кэша зеркала `HF_MIRROR_MAX_GIB` и не удаляются по LRU.
- Caddy пропускает на пути загрузки части до 80 МБ, на остальные запросы портала — до 1 МБ.

## API (администратор, с CSRF)

| Запрос | Что делает |
|---|---|
| `GET /api/admin/local-models` | каталог, загрузки (идущие, на проверке и с ошибкой за 7 дней), место на томе |
| `POST /api/admin/local-models/scan` | найти файлы в каталоге сейчас |
| `DELETE /api/admin/local-models/<имя>[?file=<файл>]` | удалить модель или файл со всеми частями; `409`, если модель используется |
| `POST /api/admin/local-models/uploads` | `{model, file, size_bytes, sha256?}` → `201`; та же незаконченная загрузка → `200` с `received_bytes` |
| `GET /api/admin/local-models/uploads/<id>` | состояние загрузки; следующая часть начинается с `received_bytes` |
| `PUT /api/admin/local-models/uploads/<id>?offset=N` | часть файла, тело `application/octet-stream`. Неверное смещение → `409` и заголовок `Upload-Offset` |
| `POST /api/admin/local-models/uploads/<id>/finish` | файл загружен целиком: `202`, дальше проверка sha256 и GGUF |
| `DELETE /api/admin/local-models/uploads/<id>` | отменить загрузку, принятая часть удаляется |
